# TI-LST 인슐레이션 통합정리

폴더 안의 TI-LST(Техномонтажная ведомость) 엑셀 파일을 모두 읽어 하나의 통합 엑셀
`INSULATION_통합정리_날짜_시간.xlsx` 로 정리합니다.

## 사용법

1. `ti_lst_reader.py` 를 TI-LST 파일들이 있는 폴더에 넣고 실행합니다 (더블클릭 또는 `python ti_lst_reader.py`).
2. 같은 폴더에 결과 파일이 만들어집니다. 시트: 통합정리데이터 / 파일별요약 / 제외라인목록 / 에러로그

- 필요 패키지: `openpyxl` (pandas는 더 이상 필요 없음), Python 3.8 이상
- 설정은 파일 위쪽 `사용자 설정` 에서 바꿉니다.

| 설정 | 설명 |
|---|---|
| `RECURSIVE` | 하위 폴더까지 검색할지 여부 |
| `SKIP_KEYWORDS` | 파일명에 이 단어가 있으면 제외 (결과 파일·임시 파일) |
| `MAX_WORKERS` | 동시에 처리할 프로세스 수 (0: 자동 = CPU 코어 수, 최대 8 / 1: 병렬 처리 안 함) |

## 성능 개선

실제 파일과 같은 구조로 만든 테스트 파일 280개(파일당 약 650행 / 200품목, 총 56,280품목), 4코어 PC 기준:

| | 기존 | 개선 후 |
|---|---|---|
| 전체 소요 시간 | 134초 | 9초 (병렬 처리 끔: 25초) |
| 최대 메모리 | 971 MB | 221 MB |
| 결과 파일 크기 | 10.7 MB | 6.5 MB |

결과 파일의 내용(4개 시트의 값, 열 너비, 틀 고정, 자동 필터, 헤더/데이터 서식)은 기존과 동일합니다.

### 느렸던 원인과 수정 내용

1. **결과 저장 (가장 큰 원인, 약 70초)**: 데이터 셀마다 `Alignment` 객체를 새로 만들어 지정하고 openpyxl 일반 모드로
   저장하던 부분입니다. 서식 2가지(헤더/데이터)만 정의한 xlsx를 직접 작성하도록 바꿔 약 2초로 줄였습니다.
2. **파일 읽기 (약 3배 빨라짐)**: `load_workbook` 일반 모드는 Cover Page, 그림, 서식까지 전부 메모리에 올립니다.
   `read_only` 모드로 대상 시트의 A:N 열만 순서대로 읽습니다.
3. **병렬 처리**: 여러 파일을 CPU 코어 수만큼 동시에 처리합니다. IDE(Spyder/Jupyter 등)에서 병렬 실행이 막히면 자동으로
   순차 처리로 다시 진행합니다.
4. pandas 제거: DataFrame은 컬럼 순서 정리에만 쓰이고 있었습니다.

### 결과가 달라지는 경우

표준 구조(라인 헤더 행 + 품목 3행 단위)의 파일은 결과가 같습니다. 아래 경우만 다릅니다.

- **병합셀 펼치기를 없앴습니다.** 라인/섹션/꼬리말 판정은 원래도 A열만 보기 때문에 표준 파일에는 영향이 없습니다.
  다만 기존 코드는 A:N으로 병합된 비정상 행(중간에 다시 나오는 섹션 행, 반복된 표 머리글 등)을 펼치면서 B열에도 값이
  생겨 **가짜 품목**으로 추출했습니다. 이제는 이런 행과, 품목 상세행 바로 다음에 오는 A열 메모 행을 품목에 붙이지 않고
  에러로그(`UNPARSED_ROW_DURING_SCAN`)에 남깁니다.
- 엑셀에 쓸 수 없는 제어문자가 셀에 있으면 제거하고 저장합니다. 기존에는 마지막 저장 단계에서 오류로 멈췄습니다.

### 기존 결과와 비교하기

기존 프로그램과 새 프로그램을 같은 폴더에서 한 번씩 실행한 뒤 `compare_results.py` 를 실행하면,
가장 최근 결과 파일 2개를 비교해 다른 항목만 보여줍니다 (`python compare_results.py 기존.xlsx 새.xlsx` 로 지정도 가능).

### 바꾸지 않은 점 (참고)

- 수식 셀은 기존처럼 수식 문자열(`=...`)로 읽습니다. 계산된 값이 필요하면 `read_sheet_rows` 의 `data_only=True` 로 바꾸면 됩니다.
- 숫자 값은 기존처럼 원본 텍스트 그대로(예: `0,011`) 저장됩니다.
- `UNPARSED_ROW_DURING_SCAN` 으로 기록된 행은 후검증에서 `UNCOVERED_MEANINGFUL_ROW` 로 한 번 더 기록됩니다.
