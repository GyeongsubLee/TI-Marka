# TI-LST 인슐레이션 통합정리

폴더 안의 TI-LST(Техномонтажная ведомость) 엑셀 파일을 모두 읽어 하나의 통합 엑셀
`INSULATION_통합정리_날짜_시간.xlsx` 로 정리합니다. EHT LIST 를 같이 넣으면 TI 보온 두께와 비교한 리포트도 만듭니다.

## 사용법

1. `ti_lst_reader.py` 를 TI-LST 파일들이 있는 폴더에 넣고 실행합니다 (더블클릭 또는 `python ti_lst_reader.py`).
   (EHT비교 COMMENT 를 TI-LST 에 옮기는 `ti_comment_writer.py` 도 같은 폴더에 둡니다)
2. 같은 폴더에 결과 파일이 만들어집니다. 시트: 통합정리데이터 / 파일별요약 / 제외라인목록 / 에러로그
   (EHT LIST 를 같이 넣었으면 뒤에 EHT비교요약 / EHT비교 시트가 추가됩니다)

- 필요 패키지: `openpyxl` (pandas는 더 이상 필요 없음), Python 3.8 이상
- 설정은 파일 위쪽 `사용자 설정` 에서 바꿉니다.

| 설정 | 설명 |
|---|---|
| `RECURSIVE` | 하위 폴더까지 검색할지 여부 |
| `SKIP_KEYWORDS` | 파일명에 이 단어가 있으면 제외 (결과 파일·임시 파일·COMMENT 파일, 대소문자 구분 안 함) |
| `MAX_WORKERS` | 동시에 처리할 프로세스 수 (0: 자동 = CPU 코어 수, 최대 8 / 1: 병렬 처리 안 함) |
| `EHT_FILE_KEYWORD` | 파일명에 이 글자(기본 `EHT`)가 있는 EHT LIST 를 TI-LST 대신 비교용으로 읽음 |
| `EHT_LENGTH_TOLERANCE` | EHT 길이와 TI 파이프 길이 차이 허용값 (기본 0.1m) |

## ISO NO 시트번호

ISO NO 뒤에 LINE NO 의 마지막 숫자(시트번호)를 붙입니다.

| LINE NO | ISO NO |
|---|---|
| `12200-24-4312/341-P44-0018-ASB0T00NN51-01 (H)` | `GCC-DLM-DDD-12200-24-4312-TKM-ISO-00094-01` |
| `...-ACB3B02SW51-03 H(REGEN)` (다른 꼬리표) | `...-ISO-00001-03` |
| `...-ASB0B02GN51-02` (꼬리표 없음) | `...-ISO-00003-02` |
| `12200-23-4312/351-F-101-XT-01 (H)` (TRIM) | `...-ISO-00075-01` |

- 끝에 붙은 `(H)`, `H(REGEN)` 같은 꼬리표는 건너뛰고 **오른쪽부터** `-숫자(1~2자리)` 로 끝나는 부분을 시트번호로 봅니다.
  TRIM(XT) 라인처럼 LINE NO 구조가 달라도 끝자리만 보므로 같은 방식으로 찾습니다.
- 시트번호를 못 찾으면 ISO NO 를 시트번호 없이 두고 에러로그에 `SHEET_NO_NOT_FOUND` 로 남깁니다.
- 제외라인목록·에러로그의 ISO NO 도 같고, 파일별요약의 `Unique ISO NO` 는 ISO 시트 단위로 셉니다.

## EHT LIST 비교

EHT LIST 엑셀을 TI-LST 파일들과 **같은 폴더**에 넣고 실행하면 됩니다.

- 파일명에 `EHT` 가 들어가야 합니다 (예: `EHT LIST.xlsx`). 이 파일은 TI-LST 로 처리하지 않습니다.
- 머리글에 `ISO NUMBER`, `Nominal Diameter`, `Thickness` 가 있는 시트를 찾아 읽습니다.
  여러 줄 병합 머리글, 위쪽 제목 행이 있어도 됩니다. 나머지 열(Length, No. of Valve, material, Operation Temp, Remark 등)도
  머리글 글자로 찾습니다.
  - 그런 시트가 여럿이면 찾은 열이 가장 많은 시트를 읽습니다.
  - 같은 머리글 열이 여럿이면 앞의 열을 쓰되, 값이 하나도 없는 열은 건너뜁니다.
- 두께가 VLOOKUP 같은 수식이면 엑셀에 저장된 계산 값을 읽습니다.
- **어느 시트·열을 읽었는지** 실행 화면(`읽은 열: ...`)과 EHT비교요약 시트의 `EHT 열 위치` 줄에 나옵니다.
  열을 못 찾았거나 값이 모두 비어 있으면(예: 수식의 계산 값이 저장되어 있지 않음) 그 이유도 함께 나오고
  에러로그에 `EHT_COLUMN_CHECK` 로 남습니다.

### 비교 방법

- EHT LIST 한 행(ISO NUMBER + Nominal Diameter)을 TI 에서 **ISO NO(시트번호 포함)와 DN 이 같은** 품목과 비교합니다.
  파이프·튜브는 길이, 밸브는 수량을 두께별로 합칩니다. 엘보/티/리듀서는 DN 이 없어 빠집니다.
- TI Note 에 `There is electric heating / Имеется электрообогрев` 표시가 있는 품목이 있으면 **그 품목만** 비교합니다
  (EHT 길이는 히팅 구간 기준). 빠진 품목은 `내용` 에 적습니다.
- EHT 가 같은 ISO 시트·DN 을 `H(INDOOR)` / `H(OUTDOOR)` 처럼 나눠 적었으면 TI 도 같은 보온구분 라인끼리 비교합니다.
- 한 ISO 시트에 라인이 여럿이면 EHT 라인번호(예: `302-HS-0002`)가 들어 있는 TI 라인만 비교합니다.
- **TI 최소 두께**: 행마다 비교한 TI 파이프·밸브를 모두 합쳐 가장 얇은 두께를 보여줍니다. 보온이 가장 얇은 경우가
  열손실(Load)이 가장 크므로, EHT LIST 에는 이 값을 보수적으로 반영하면 됩니다.
  EHT 두께가 이 값과 다르면 `두께 변경 필요` 가 `Y` 입니다.
- **온도**: EHT `Operation Temp` 와 TI `Temperature` 를 비교해 `온도 판정` 에 적습니다 (두께 판정과 따로).
  `70` 은 같은 값, `0.5 ~ 25` 는 범위 안, `37 / 290` 은 둘 중 하나와 같으면 `일치` 이고,
  `AMB` 처럼 숫자가 아니거나 TI 온도가 없으면 `비교 불가` 입니다. TI 온도가 여럿이면 모두 맞아야 `일치` 입니다.

예) EHT LIST 는 3m 가 THK 30 인데 TI 는 30mm 1m + 20mm 2m 인 경우 → 판정 `두께 혼재`, EHT 두께 비율 `33.3`%,
TI 최소 두께 `20`, 두께 변경 필요 `Y`, 내용 `EHT 두께가 아닌 부분: 20mm 2.00m`

### 판정 (EHT비교 시트, 건수는 EHT비교요약 시트)

| 판정 | 뜻 |
|---|---|
| 일치 | TI 파이프·밸브 두께가 모두 EHT 두께와 같고 길이 차이도 허용값 이내 |
| 길이 차이 | 두께는 같지만 EHT 길이와 TI 파이프 길이 차이가 허용값보다 큼 |
| 두께 혼재 | TI 에 EHT 두께와 다른 두께가 섞여 있음 (`EHT 두께 비율` 확인) |
| 두께 불일치 | TI 에 EHT 두께가 없음 |
| TI에 DN 없음 | TI 에 ISO 시트는 있으나 해당 DN 파이프/밸브가 없음 (`내용` 에 그 시트의 TI DN 목록) |
| TI에 ISO 없음 | TI-LST 에 해당 ISO 시트가 없음 |
| TI 제외라인 | TI 에서 제외(Excluded)된 라인에만 있음 |
| EHT에 없음 | TI 에는 전기히팅 표시가 있는데 EHT LIST 에 해당 ISO 시트·DN 이 없음 (EHT비교 시트 맨 뒤) |
| 비교 제외 | Pumping Trap, DN 이 `40x20` 처럼 숫자 하나가 아님, ISO/두께 없음(`#N/A` 등), 길이·밸브 0 이고 TI 에 DN 없음 |

| 주요 열 | 내용 |
|---|---|
| TI 최소 두께 (mm) / 두께 변경 필요 | TI 파이프·밸브 중 가장 얇은 두께 / EHT 두께와 다르면 `Y`, 같으면 `N` (두께를 비교한 행만) |
| TI 파이프 두께별 길이 | 예: `20mm 2.00m, 30mm 1.00m` (밸브는 `TI 밸브 두께별 수량`) |
| TI 중 EHT 두께 길이 / EHT 두께 비율 (%) | TI 파이프 길이 중 EHT 두께인 길이와 비율 (파이프가 없으면 밸브 수량 기준) |
| 길이 차이 (m) | TI 파이프 길이 − EHT 길이 |
| EHT 운전온도 (℃) / TI 온도 (°C) / 온도 판정 | EHT Operation Temp, TI 온도(여럿이면 `20, 25`), `일치` / `다름` / `비교 불가` |
| 내용 | 판정 이유, 비교에서 뺀 품목, 길이·밸브 수량 차이 |
| EHT 행 | EHT LIST 파일의 행 번호 |
| COMMENT (AC열) | 비어 있음. 여기 적은 코멘트를 `ti_comment_writer.py` 가 TI-LST 에 옮겨 적음 (아래) |

## COMMENT 를 TI-LST 에 옮기기 (`ti_comment_writer.py`)

1. 결과 파일 `EHT비교` 시트의 맨 끝 `COMMENT` 열(AC)에 코멘트를 적습니다.
2. 파일명에 `COMMENT` 가 들어가게 저장합니다 (예: `EHT비교_COMMENT.xlsx`). 그 시트만 따로 저장해도 되고,
   코멘트를 적은 행만 남겨도 됩니다.
3. 그 파일을 TI-LST 파일들이 있는 폴더(`ti_lst_reader.py` 와 같은 폴더)에 넣고 `ti_comment_writer.py` 를 실행합니다.
   시작할 때 COMMENT 를 적을 품목을 고릅니다 (엔터 = 1).
   - `1) 전기히팅 표시 품목에만` (기본): TI Note 에 `There is electric heating / Имеется электрообогрев` 가 있는
     품목에만 적습니다. 한 라인에 히팅 구간과 아닌 구간이 섞여 있으면 **히팅 구간만** 적고, 히팅 표시 품목이 없으면
     적지 않습니다.
   - `2) 비교한 품목 전체`: 히팅 표시와 관계없이 비교한 품목 모두에 적습니다.
   - `3) 1번 + Note 누락 판단`: EHT LIST 에 있는 행인데 비교한 TI 품목 **모두** Note 에 히팅 표시가 없으면, Note 가
     빠진 것으로 보고 그 품목 모두에 적습니다 (반영결과에 `품목 행에 적음 (Note 누락으로 봄)`).
     그 외(히팅 구간과 아닌 구간이 섞인 행, TI 에만 있는 `EHT에 없음` 행)는 1번과 같습니다.
   - 붙일 TI 품목이 없는 COMMENT(TI에 ISO 없음 등, TI에 없는 라인)는 1, 2, 3 모두 **데이터 끝에 추가**합니다.
   - 묻지 않게 하려면 실행할 때 `--heating` / `--all` / `--note-missing` 을 붙이거나 파일 위쪽 `COMMENT_SCOPE` 를
     `"heating"` / `"all"` / `"note-missing"` 으로 둡니다.
4. `OUTPUT TI COMMENT` 폴더에 `원래이름_COMMENT.xlsx` 가 만들어집니다. 원본 TI-LST 는 바뀌지 않습니다.

| EHT비교 행 | TI-LST 에 적는 곳 (O열) |
|---|---|
| TI 와 비교한 행 (일치, 길이 차이, 두께 혼재/불일치, TI 제외라인, EHT에 없음) | 비교에 쓴 TI 품목(같은 ISO 시트·DN 의 파이프·밸브)의 품목 행. 엘보/티/리듀서에는 적지 않음 |
| 붙일 품목이 없는 행 (TI에 ISO 없음, TI에 DN 없음 등) | 그 ISO 시트가 있는 TI-LST, 없으면 같은 구역에서 ISO 번호가 가장 가까운 TI-LST 의 **데이터가 끝난 다음 행부터** 차례로 적은 COMMENT 그대로 |

- 같은 품목에 COMMENT 가 여러 개면 ` / ` 로 이어 붙이고, 원본 O열에 이미 값이 있으면 그 뒤에 붙입니다.
- COMMENT 에 두께가 하나만 적혀 있으면(예: `thickness shall be 50mm`, `Thk 50`, `두께 50`) **이미 그 두께인 품목에는
  적지 않습니다**. 예) 두께 혼재 행에서 파이프 50mm·밸브 40mm 이면 밸브에만 적음.
  두께가 여러 개 적혀 있으면(예: `40 -> 50mm`) 모든 품목에 적습니다. 끄려면 `SKIP_SAME_THICKNESS = False`.
- 어디에 적었는지는 `OUTPUT TI COMMENT/COMMENT_반영결과_날짜_시간.xlsx` 에 남습니다
  (적지 못한 COMMENT 와 이유, 이미 같은 두께라 `적지 않음 (이미 50mm)` 인 품목,
  히팅 표시가 없어 `적지 않음 (전기히팅 표시 없음)` 인 품목, 3번에서 `Note 누락으로 봄` 으로 적은 품목 포함).
  TI 품목마다 TI 도서의 품명·Size·DN·`Temperature (°C)`·`Name (designation)`(H열 보온재 이름)·두께·
  `Length (m)`·`Volume of thermal insulation layer (m³)`·`Note` 도 같이 나옵니다
  (Temperature·Length·체적은 숫자로 들어가서 엑셀에서 바로 계산할 수 있음).

결과 파일 모양

- O열 머리글 `Comment` (N열 Note 머리글과 같은 서식 + 노란색, N열이 2~3행 병합이면 O열도 병합), O열 너비 40 이상
- COMMENT 를 적은 행(품목 행·추가한 행)과, 어느 라인인지 알 수 있게 그 품목의 **라인 머리글 행**
  (`Pipeline / Трубопровод - ...`)은 A~O열 노란색 음영 (원래 글꼴·테두리는 그대로)
- **노란색 행만 보이게 필터를 건 채로** 저장됩니다 (O열 `색 기준 필터` = 노란색, 필터 단추에서 확인을 다시 눌러도
  같은 행이 보임). 전체를 보려면 O열(3행) 필터 단추에서 필터 해제 (데이터 → 지우기)
- 보기는 `기본` (페이지 나누기 미리 보기였어도 기본 보기로 바꿈)
- 그 밖의 내용(서식, 병합, 그림, 머리글/바닥글, 인쇄 영역 등)은 원본 그대로입니다.
- TI 품목은 결과 파일을 만들 때와 같은 규칙으로 다시 찾습니다. 그 사이 TI-LST 가 바뀌었으면 결과 파일을 다시 만든 뒤
  COMMENT 를 적으세요.
- `ti_lst_reader.py` 를 같은 폴더에 두어야 합니다 (예전 버전이어도 동작하지만 같이 받은 최신 버전으로 바꿔 두세요).
- 처리 시간: TI-LST 100개, COMMENT 2,200건 기준 약 18초
- 설정(파일 위쪽): `COMMENT_FILE_KEYWORD`, `OUTPUT_FOLDER`, `OUTPUT_SUFFIX`, `COMMENT_COLUMN`(기본 `O`),
  `COMMENT_HEADER`(머리글), `COMMENT_COLUMN_WIDTH`(O열 너비), `HIGHLIGHT_COLOR`(음영 색, `None` 이면 음영 없이
  O열 '비어 있지 않음' 필터), `FILTER_COMMENT_ROWS`(필터), `NORMAL_VIEW`(기본 보기),
  `SKIP_SAME_THICKNESS`(같은 두께 품목 제외), `COMMENT_SCOPE`(적을 품목: `None` 시작할 때 물어봄 / `"heating"` / `"all"` / `"note-missing"`),
  `APPEND_FORMAT`(데이터 끝에 추가할 때 형식, 기본은 COMMENT 만. 예: `"{iso} / {line} / DN {dn}: {comment}"`)

## Nominal Diameter(DN) 지정 규칙

| 품명 | 기준 | 표 |
|---|---|---|
| `TUBE` 포함 | 품명의 `TUBING SIZE: 3/4 INCH` 인치 값 (1/8" → `-`) | `TUBE_SIZE_TO_DN` |
| `VALVE` 포함 | Size 값이 곧 호칭경 (`25,0` → DN 25). DN 값이 아니면(외경을 적은 경우) 외경으로 찾음 | `OD_TO_DN_MAP` |
| `Pipe` / `Труба` 포함 | Size 열의 외경(mm), ±0.3mm 이내 | `OD_TO_DN_MAP` |
| 그 외 (엘보, 티, 리듀서 등) | DN 지정 안 함 | - |

표에 없는 규격은 빈칸으로 나옵니다. 규격을 추가하려면 파일 위쪽의 두 표에 한 줄씩 추가하면 됩니다
(예: `"1-1/2": "DN 40",`, `1371.60: "DN 1350",`).

### 느렸던 원인과 수정 내용

1. **결과 저장 (가장 큰 원인, 약 70초)**: 데이터 셀마다 `Alignment` 객체를 새로 만들어 지정하고 openpyxl 일반 모드로
   저장하던 부분입니다. 서식 2가지(헤더/데이터)만 정의한 xlsx를 직접 작성하도록 바꿔 약 3초로 줄였습니다.
2. **파일 읽기 (파일당 165ms → 75ms 정도)**: `load_workbook` 일반 모드는 Cover Page, 그림, 서식까지 전부 메모리에 올립니다.
   `read_only` 모드로 대상 시트의 A:N 열만 순서대로 읽습니다.
3. **병렬 처리**: 여러 파일을 CPU 코어 수만큼 동시에 처리합니다. IDE(Spyder/Jupyter 등)에서 병렬 실행이 막히면 자동으로
   순차 처리로 다시 진행합니다.
4. pandas 제거: DataFrame은 컬럼 순서 정리에만 쓰이고 있었습니다.

### 결과가 달라지는 경우

표준 구조(라인 헤더 행 + 품목 3행 단위)의 파일은 결과가 같습니다. 아래 경우만 다릅니다.

- **병합셀 펼치기를 없앴습니다.** 라인/섹션/꼬리말 판정은 원래도 A열만 보기 때문에 표준 파일에는 영향이 없습니다.
  다만 기존 코드는 A:N으로 병합된 비정상 행(중간에 다시 나오는 섹션 행, 반복된 표 머리글 등)을 펼치면서 B열에도 값이
  생겨 **가짜 품목**으로 추출했습니다. 이제는 이런 행과, 품목 상세행 바로 다음에 오는 A열 메모 행을 품목에 붙이지 않고
  에러로그(`UNPARSED_ROW_DURING_SCAN`)에 남깁니다.
- 엑셀에 쓸 수 없는 제어문자가 셀에 있으면 제거하고 저장합니다. 기존에는 마지막 저장 단계에서 오류로 멈췄습니다.

### 기존 결과와 비교하기

기존 프로그램과 새 프로그램을 같은 폴더에서 한 번씩 실행한 뒤 `compare_results.py` 를 실행하면,
가장 최근 결과 파일 2개를 비교해 다른 항목만 보여줍니다 (`python compare_results.py 기존.xlsx 새.xlsx` 로 지정도 가능).

ISO NO 에 시트번호를 붙이기 전 결과와 비교하면 모든 행의 ISO NO(`...-ISO-00094` -> `...-ISO-00094-01`)와
파일별요약의 `Unique ISO NO` 가 다르게 나오는 것이 정상입니다. EHT 시트는 "새 결과에만 있는 시트"로 표시됩니다.

### 바꾸지 않은 점 (참고)

- 수식 셀은 기존처럼 수식 문자열(`=...`)로 읽습니다. 계산된 값이 필요하면 `read_sheet_rows` 의 `data_only=True` 로 바꾸면 됩니다.
- 숫자 값은 기존처럼 원본 텍스트 그대로(예: `0,011`) 저장됩니다.
- `UNPARSED_ROW_DURING_SCAN` 으로 기록된 행은 후검증에서 `UNCOVERED_MEANINGFUL_ROW` 로 한 번 더 기록됩니다.
